def wilson(k, n, z=1.96):
    if n == 0:
        return (0.0, 0.0)
    p = k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = (z / d) * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return (max(0.0, c - h) * 100, min(1.0, c + h) * 100)

h1("1. Introduction")
para(
    "A forensic examiner who images a disk hopes to find an intact filesystem: a "
    "directory that names every file and records where its bytes physically live. Often "
    "that structure is gone. When a file is deleted, modern filesystems do not erase its "
    "contents; they erase the bookkeeping that points to them. ext3, for instance, "
    "zeroes an inode's block pointers the moment a file is unlinked (Carrier, 2005). "
    "Many images also arrive with the partition table destroyed, the volume reformatted, "
    "or the medium copied raw from failing hardware. In these cases the bytes of a file "
    "are usually still present on the disk, but nothing records which sectors belong to "
    "which file, or in what order. Recovering files from those raw bytes alone, without "
    "any filesystem metadata, is called file carving, and it is the recovery method of "
    "last resort in digital forensics."
)
para(
    "What makes carving hard is fragmentation. A disk is divided into fixed-size blocks "
    "(sectors of 512 bytes on the media studied here), and a file is stored as a list of "
    "those blocks. A filesystem tries to place a file's blocks consecutively, but as a "
    "volume fills and files are written, edited, and deleted, free space breaks into "
    "scattered gaps, and a new file is spread across whichever gaps are available. The "
    "file is then fragmented: its blocks are physically out of order, with runs of "
    "unrelated data from other files sitting between them. While the filesystem is "
    "intact this is invisible, because the directory records the exact block list. Once "
    "that record is lost, a carver sees only a long sequence of sectors with no "
    "indication of where one file ends, another begins, or how the pieces of a "
    "fragmented file fit back together. The Portable Document Format (PDF) is a frequent "
    "and high-value carving target. It is the de facto format for contracts, reports, "
    "and scanned correspondence, and it fragments readily, because a PDF is usually "
    "saved or revised alongside other documents that compete for the same free space."
)
para(
    "The first generation of carvers (Scalpel (Richard and Roussev, 2005), Foremost "
    "(Kornblum and Kendall, 2010), and PhotoRec (Grenier, 2007)) scan for a known header "
    "signature such as %PDF- and copy bytes forward until they reach a footer or a size "
    "limit. This is fast and format-agnostic, and it works whenever a file occupies one "
    "contiguous run of sectors. It fails completely on a fragmented file: the span "
    "between header and footer then contains sectors belonging to other files, so the "
    "carver either truncates the document at its first fragment or splices in foreign "
    "bytes, an outcome that is worse than useless in an evidentiary setting, because the "
    "spliced file misleads the examiner. These tools also carry no model of a file's "
    "internal structure, so they cannot tell a sound reconstruction from a corrupt one."
)
para(
    "Cohen (2007) reframed the problem in a way that still defines the field. A "
    "structured format, he observed, carries inside itself enough information to guide "
    "its own reassembly. He cast carving as the recovery of a mapping function between "
    "offsets in the logical file and offsets in the disk image, and showed that PDF "
    "supplies the anchors that pin that function down. Every PDF ends with a "
    "cross-reference (xref) table that lists the byte offset of each indirect object in "
    "the file. Each entry therefore fixes one point on the mapping function: a file "
    "offset whose disk location is found by searching the image for the matching object "
    "header at a sector-aligned position. We call such a fixed point an identified "
    "point, or anchor. Between two anchors the carver interpolates with unit slope, and "
    "where its forward and backward interpolations disagree it has found a fragment "
    "boundary, which it resolves by trial-fitting candidate split points and re-parsing "
    "the result with a stateful PDF tokeniser, a discriminator that reports not just "
    "whether a reconstruction is wrong but where it first goes wrong. Cohen's "
    "implementation recovered several heavily fragmented PDFs from the DFRWS 2007 "
    "challenge and has been the reference baseline for PDF carving ever since."
)
para(
    "The model is sound, but the implementation was written against the PDFs and disk "
    "layouts of its time, and two of its assumptions no longer hold for the documents an "
    "examiner meets today. Each produces a concrete, measurable failure."
)
para(
    "Modern cross-reference encoding. Since PDF 1.5 (2003), the classic xref table may "
    "be replaced by a cross-reference stream: the same offset information, but stored "
    "inside an object, compressed with FlateDecode (the zlib/Deflate algorithm; Deutsch, "
    "1996) and usually pre-processed with a PNG row predictor, rather than written as "
    "plain text. This is now the default output of Chrome's and Firefox's \"Print to "
    "PDF\", Microsoft Word, LibreOffice, and Acrobat since 2008, that is, of almost "
    "every document produced today. A carver that looks only for the literal keyword "
    "xref finds nothing in these files, derives no anchors, and recovers nothing at all. "
    "The failure is silent and near-universal.", bold_lead="FM1.")
para(
    "Intra-object fragmentation. When a single object's compressed stream is split "
    "across two disk fragments, the break falls strictly between two consecutive anchors "
    "and is marked by nothing in the file. The carver reads straight through the gap, "
    "splicing unrelated sectors into the middle of the stream; the FlateDecode "
    "decompression then fails, and the page that the stream encodes does not render. "
    "Cohen's discriminator can tell that something is wrong from a rising error count "
    "but, by his own account, cannot in general say where the break is, and that error "
    "count is least reliable exactly when the cross-reference structure is damaged. This "
    "intra-object split is the dominant fragmentation mode for compressed document "
    "streams, and the canonical model has no mechanism to repair it.", bold_lead="FM2.")
para(
    "Beyond these two failures, the original tool has three properties that keep it from "
    "being usable in practice rather than only in principle. It validates a "
    "reconstruction with the same parser that produced it, so a syntactically clean file "
    "with a corrupt compressed stream is accepted while a sound document with a damaged "
    "xref is rejected. It reconstructs an incrementally-updated document once for every "
    "cross-reference table the file contains, inflating the recovered-file count with "
    "near-duplicate copies. And it extrapolates past its last anchor without bound, so a "
    "file whose xref covers only its early objects is over-read across hundreds of "
    "megabytes of unrelated disk content."
)
para(
    "This paper takes the position that the Cohen model is the right model and that what "
    "it needs is extension, not replacement. We keep its mathematical core unchanged "
    "(the mapping function, the sector-modulus rule, the projection-line test, and the "
    "stateful-lexer discriminator) and extend the machinery around it. Two extensions "
    "are the substantive contributions of this work; the remainder are engineering "
    "changes that make the tool usable in practice. We evaluate the result honestly "
    "against the original Cohen carver, the Chen et al. (2008) validation carver, and "
    "three production carvers, on real and controlled data, with one scoring procedure "
    "applied identically to the raw output of all six tools."
)
para(

)

# ===================== 2. Background and Related Work =====================
h1("2. Background and Related Work")
para(
    "Pal and Memon (2009) trace the development of carving from naive signature "
    "extraction toward fragment-aware reassembly, and their survey draws the distinction "
    "that organises this section: between syntactic carvers, which treat a file as an "
    "opaque byte range bounded by signatures, and semantic carvers, which parse the "
    "format and exploit its internal structure. The tools an examiner reaches for first "
    "are still mostly syntactic; the model we extend is semantic."
)
h2("2.1 Syntactic carvers")
para(
    "Scalpel (Richard and Roussev, 2005), Foremost, and PhotoRec (Grenier, 2007) are the "
    "canonical header/footer carvers. Each scans the image for a known start signature, "
    "such as %PDF-, and copies bytes forward to a matching footer or a size limit, "
    "guided by a database of signature pairs. They are fast and format-agnostic, work "
    "well on contiguous files, and remain the first-line tools in most laboratories. "
    "Their ceiling is structural: because they assume a file occupies one contiguous run "
    "of sectors, they cannot reassemble a fragmented file, and because they do not parse "
    "content, they cannot distinguish a sound reconstruction from a corrupt one. Our own "
    "measurements (Section 5) show the consequence starkly: on the out-of-order "
    "fragmentation scenarios, the signature carvers' exact recovery falls to zero."
)
para(
    "A recent development in syntactic carving is Hughes and Black (2024), who carve "
    "PDFs by scanning the image in one-kibibyte segments for body-level markers (the "
    "version header, the xref keyword, and the /Size, /Root, and /Info dictionary keys) "
    "and accept a region as a PDF when at least four of the five are present. Reading "
    "body markers rather than the header makes their method resilient to file-signature "
    "obfuscation, an anti-forensic technique that alters a file's first and last bytes, "
    "and they recover 93.4% of obfuscated PDFs where Scalpel recovers none. Their "
    "technique is orthogonal to ours: it targets header obfuscation, not fragmentation, "
    "and the authors state plainly that fragmentation is not addressed, their test files "
    "being small and stored contiguously on a clean drive."
)
h2("2.2 PDF cross-reference structures")
para(
    "A PDF is a sequence of indirect objects framed by a %PDF- header and a %%EOF "
    "marker. Because a reader reaches objects by random access rather than by reading "
    "sequentially, every PDF carries a cross-reference structure that records the byte "
    "offset of each object. This structure takes one of three forms, shown in Figure 1, "
    "and the difference is decisive for a structure-driven carver."
)
para(
    "Traditional cross-reference table. Through PDF 1.4, and still in many later "
    "documents, the offsets are written as a plain-text table introduced by the keyword "
    "xref and followed by a trailer dictionary and a startxref pointer (Figure 1a). A "
    "carver locates this table simply by scanning for the literal keyword."
)
para(
    "Cross-reference stream. PDF 1.5 (2003) permits the table to be replaced by a "
    "cross-reference stream: a single object of /Type /XRef whose entries are packed as "
    "fixed-width binary records, compressed with FlateDecode and usually pre-processed "
    "with a PNG row predictor (Figure 1b). There is no xref keyword anywhere in the "
    "file; startxref points directly at the stream object. This is the default output "
    "of current browsers' Print to PDF, Microsoft Word, LibreOffice, and Acrobat, and "
    "is therefore the common case in present-day evidence."
)
para(
    "Hybrid reference. For backward compatibility a document may carry both forms at "
    "once: a classic xref table covering the objects an old reader needs, and a "
    "cross-reference stream covering the rest, linked by an /XRefStm entry in the "
    "trailer (Figure 1c). An old reader follows the table; a PDF-1.5-aware reader "
    "follows the stream."
)
para(
    "The consequence for carving is direct. A carver that recognises only the xref "
    "keyword handles the traditional form and, through its classic table, the hybrid "
    "form, but is blind to the pure cross-reference stream: it finds no offsets and "
    "recovers nothing. That is precisely the FM1 failure of Section 1, and recovering "
    "identified points from the cross-reference stream is the first contribution of "
    "this work."
)
figure(r"<repo>\figures\fig1_xref.png", 6.4,
       "Figure 1. The three forms of PDF cross-reference structure. Shaded blocks hold "
       "the offset information a structure-driven carver depends on: a plain-text "
       "table (a), a single compressed /Type /XRef object (b), or both, linked by an "
       "/XRefStm entry (c). A carver that scans only for the xref keyword cannot see "
       "the compressed stream of (b).")
h2("2.3 Cohen's mapping-function model")
para(
    "Cohen (2007) reframed carving as the estimation of a mapping function between "
    "offsets in the logical file and offsets in the disk image. The function is "
    "piecewise-linear with unit slope, injective (no image byte is used twice) and "
    "breaks only at sector boundaries, which yields the modulo rule mod(x, s) = "
    "mod(y, s) for sector size s. Cohen decomposed an advanced carver into three parts: "
    "a generator that proposes candidate mappings, a discriminator that rates their "
    "validity and, ideally, localises corruption, and a set of positively identified "
    "points deduced from internal structure that constrain the generator. For PDF, the "
    "cross-reference table supplies those points: each in-use entry records an object's "
    "byte offset, fixing one point on the mapping function whose disk location is found "
    "by searching for the object header at a sector-congruent position. Ambiguous "
    "regions between points are resolved by inserting candidate split points and "
    "re-parsing with a stateful PDF tokeniser whose rising error count signals a "
    "discontinuity. We adopt this model and its terminology unchanged."
)
para(
    "Two properties of the original are central to our work. First, it derives "
    "identified points only from the classic xref table, recognised by the literal "
    "keyword xref; the cross-reference stream is not addressed. Second, Cohen notes "
    "that for a compressed stream the discriminator typically detects an error only a "
    "few sectors after the discontinuity and cannot, in general, localise the break, "
    "and that the error count is least reliable precisely when the cross-reference "
    "structure is damaged. These two properties are the failure modes FM1 and FM2 of "
    "Section 1."
)
h2("2.4 Fragment validation and reassembly by decoding")
para(
    "Garfinkel (2007) introduced fast object validation and bifragment gap carving: "
    "initial points are placed by header and footer detection, and a fast validator "
    "accepts or rejects candidate reconstructions while the gap between two fragments "
    "is grown sector by sector. This established the discriminator that recurs "
    "throughout fragment-aware carving (a reassembly is almost certainly correct when "
    "it decodes to completion), and it is the conceptual origin of the oracle our "
    "repair stage uses."
)
para(
    "Chen et al. (2008) developed this validation idea specifically for PDF, proposing "
    "five layered checks: header and object-offset validation, internal-structure "
    "validation, an entropy-difference test for locating compressed-stream boundaries, "
    "a zlib/deflate decompression test, and a font character-table test. Two of these "
    "bear directly on our second contribution. Their intact-object validation uses the "
    "cross-reference offsets to bound each object, and their decompression test "
    "reassembles a bifragmented compressed stream by iterating the split sector by "
    "sector, concatenating the two fragments, and decompressing until the result is "
    "valid. Taken together, Chen et al. already perform an xref-bounded, "
    "decompression-validated repair of a bifragmented compressed PDF stream. We build "
    "directly on this; both the decompression-completeness oracle and the use of "
    "cross-reference offsets to bound the search are theirs, not ours. What we add "
    "(Section 3) is the integration of that search into Cohen's mapping-function model "
    "(a single bounded search between two consecutive identified points) and, through "
    "our cross-reference-stream decoder, its application to the modern xref-stream "
    "documents that Chen et al.'s classic-table method cannot parse. Chen et al. also "
    "recorded the operational weaknesses of Cohen's implementation that motivate our "
    "engineering contributions: that it generated much redundant output, producing two "
    "or three copies of some documents, and required manual intervention when an error "
    "could not be resolved."
)
para(
    "Beyond PDF, Poisel et al. (2011), extending the Smart-Carving architecture of Pal "
    "and Memon, formalise the preprocessing-collation-reassembly pipeline for "
    "fragmented multimedia files and analyse the cost of reassembly: naive permutation "
    "of fragments is factorial, reduced to roughly O(n2 log n) by weighted-graph "
    "methods such as Greedy Parallel Unique Path. Their analysis is a reminder of why "
    "structural anchors matter so much, since every positively-identified point removes "
    "a dimension from the reassembly search, which is exactly what the cross-reference "
    "table provides for PDF. Poisel et al. and Garfinkel both also caution that a "
    "decoder used as a validator can accept semantically-invalid data without "
    "complaint; relying on the carver's own parser is the strongest form of that "
    "hazard, and it motivates the independent validator we describe in Section 3. "
    "Broader surveys of fragmented-file and multimedia carving, for example Pahade et "
    "al. (2015), group these methods into traditional, smart, and modern carving and "
    "reach the same conclusion: fragmentation and compression are the two standing "
    "obstacles."
)
para(
    "A separate and growing line of work applies statistical and machine-learning "
    "methods to the carving problem, most often to fragment type classification, "
    "deciding from a block's byte statistics which file type it belongs to, and to "
    "predicting fragmentation points. These methods are largely complementary to ours "
    "and address a different sub-problem: they help decide which blocks are candidate "
    "PDF content in the first place, whereas our contribution assumes the PDF blocks "
    "are identifiable (by header, keyword, and cross-reference structure) and concerns "
    "how to order and validate them. A learned classifier could in principle supply or "
    "prioritise candidate blocks for the structural stage we describe, but a "
    "structure-driven carver still needs the format-specific reasoning, cross-reference "
    "decoding and decompression-validated reassembly, that is the subject of this "
    "paper; we therefore treat learned fragment classification as an orthogonal input "
    "rather than a competing approach, and do not evaluate against it."
)
h2("2.5 PDF repair versus PDF carving")
para(
    "A separate line of work repairs already-extracted but corrupted PDFs rather than "
    "carving them from raw media. The recent REPDF framework of Park et al. (2026), in "
    "this journal, reconstructs object relationships and remaps fonts from a pre-built "
    "font database, recovering text from damaged files across ten corruption "
    "scenarios. Its input is a damaged file, not a disk image, and its objective is to "
    "maximise renderable content from that file. Our work addresses the prior step "
    "(recovering the file from unallocated sectors) and treats rendering only as a "
    "binary validity test, not a content-recovery goal. The two are complementary: a "
    "carver such as ours could supply candidate files to a repair framework such as "
    "REPDF. The overlap is telling in one respect: Park et al.'s corruption scenarios "
    "for cross-reference removal and font-stream loss are precisely the conditions "
    "under which a naive carver fails, and which our damaged-xref fallback and "
    "independent validator are designed to survive."
)
h2("2.6 The gap we address")
para(
    "Two gaps remain after this body of work, and they map onto our two contributions. "
    "First, no PDF carver derives identified points from cross-reference streams: the "
    "canonical model, and every semantic carver built on it, recovers nothing from PDF "
    "1.5+ documents, which are now produced by default by every mainstream tool (the C1 "
    "gap). Second, although decompression-validated repair of a bifragmented compressed "
    "stream exists (Chen et al. bound it by cross-reference offsets and validate it by "
    "deflate completeness), it has been demonstrated only for classic-xref PDFs and "
    "only as a standalone validation cascade, never anchored to the identified points "
    "of the mapping-function model and never applied to the modern documents that the "
    "first gap renders unreadable (the C2 gap). We close the first gap by decoding "
    "cross-reference streams, and the second by re-anchoring the "
    "decompression-validated search to two consecutive identified points and extending "
    "it, through the first, to modern PDFs, all while keeping Cohen's mathematical core "
    "intact."
)

# ============================ 3. Methodology ==============================
h1("3. Methodology")
h2("3.1 Problem formalisation")
para(
    "We adopt the carving model of Cohen (2007). An acquired disk image is a byte "
    "sequence I[0..M) and a target file is F[0..L). Carving is the recovery of a "
    "mapping function phi that assigns to each file offset the image offset holding its "
    "byte. The function is piecewise of unit slope, injective (no image byte is used "
    "twice) and breaks only at sector boundaries; its discontinuities are the points of "
    "fragmentation. A positively identified point, or anchor, is a pair (x, phi(x)) "
    "deduced with high confidence from the file's internal structure. For PDF, each "
    "in-use cross-reference entry is one anchor: it gives a file offset x, and the "
    "matching object header is located in the image at a sector-congruent position y "
    "satisfying the modulo rule mod(x, s) = mod(y, s) for sector size s = 512 bytes."
)
para(
    "Within this model the two failure modes of Section 1 are precise. FM1 is the "
    "absence of any derivable anchor: when the cross-reference information is encoded "
    "as a stream rather than a classic table, no offsets are extracted and phi has no "
    "fixed points. FM2 is an unmarked discontinuity strictly between two adjacent "
    "anchors: when a single object's compressed stream is bi-fragmented, the break lies "
    "inside the interval between object N and object N+1, where no structural token "
    "records its position."
)
h2("3.2 System overview")
para(
    "The extended carver implements Cohen's generator-discriminator architecture in "
    "three stages, shown in Figure 2. Stage 1 builds a structural index of the image in "
    "a single pass (E1). Stage 2 derives anchors and generates candidate mappings, "
    "drawing them from classic xref tables, from cross-reference streams (C1), and, "
    "when no anchor survives, from document-boundary scanning (E3); cross-reference "
    "structures belonging to one document are merged so each is reconstructed once "
    "(E5). Stage 3 materialises each candidate mapping into a PDF, repairs bifragmented "
    "streams (C2), validates each output with an independent renderer (E4), clamps it "
    "against over-read (E6), and deduplicates the accepted files (E5)."
)
para(
    "Each stage leaves a persistent artefact, which matters for auditability as much "
    "as for engineering. Stage 1 writes the keyword index to disk (index.idx), so the "
    "expensive linear scan runs once per image. Stage 2 writes one plain-text map file "
    "per candidate document: each line pairs a logical file offset with the image "
    "offset that supplies it, and a bound directive records where reconstruction must "
    "stop. Stage 3 writes the reconstructed PDFs into an output directory, moves every "
    "intermediate (maps, index, rejected and duplicate files, and the repair log) into "
    "a working subdirectory rather than deleting it, and emits a per-file results "
    "table recording each candidate's validation verdict and deduplication label. "
    "Nothing produced during a run is destroyed by the run: a second examiner can "
    "re-trace every reconstruction from the retained artefacts."
)
figure(r"<repo>\figures\fig2_pipeline.png", 4.2,
       "Figure 2. The pipeline. Stage 1 indexes the structural keywords with an "
       "Aho-Corasick automaton. Stage 2 parses each cross-reference region, deriving "
       "anchors from a classic xref table, a decoded cross-reference stream (C1), a "
       "synthetic xref rebuilt from surviving object headers, or a header-to-EOF "
       "document scan (E3). Stage 3 reconstructs one PDF per map, repairs bifragmented "
       "FlateDecode streams (C2), render-verifies each candidate with an independent "
       "parser (E4), and classifies it as a distinct recovered PDF, a duplicate, or a "
       "suspect file (E5).")
h2("3.3 Stage 1: single-pass structural indexing (E1)")
para(
    "Problem. Cohen's preprocessing scans the image once per keyword with a separate "
    "regular-expression pass over fixed blocks. This costs O(kN) for k keywords over N "
    "bytes and, more seriously, silently drops any keyword whose bytes straddle a block "
    "boundary, because neither adjacent block contains the whole pattern."
)
para(
    "Change (E1). A single pass of an Aho-Corasick automaton (Aho and Corasick, 1975) "
    "locates every keyword of interest at once (obj, xref, startxref, the document "
    "markers %PDF- and %%EOF, and the /XRef marker that flags a cross-reference stream) "
    "in time linear in the image. Each automaton hit is confirmed by the original "
    "anchored regular expression over a short neighbourhood and is accepted only when "
    "the keyword ends exactly at the hit, which rejects substrings beginning "
    "mid-digit-run. Adjacent 4 MiB blocks overlap by 64 bytes, more than the longest "
    "keyword, so a straddling match is always wholly contained in one block."
)
para(
    "Why it helps. The single pass is the dominant cost of indexing, so collapsing k "
    "passes into one drives most of the speed-up reported in Section 5, and the overlap "
    "fixes a latent correctness bug, not only a performance one. The same automaton "
    "carries the markers that C1 and E3 require, so E1 also enables them."
)
h2("3.4 Stage 2: anchor derivation and candidate mapping")
para(
    "For each cross-reference region the carver forms an anchor (x, y) for every in-use "
    "object and confirms y by seeking to the candidate image offset and matching the "
    "'N G obj' header; only sector-congruent candidates are tried. Cross-reference "
    "structures belonging to one document are coalesced by following the /Prev chain. "
    "When no usable anchor survives (a corrupt or absent cross-reference section), "
    "document spans are delimited directly from the %PDF- and %%EOF markers (E3): each "
    "header is paired with the last %%EOF before the next header, which is the "
    "fully-updated revision, and the span is carried forward as a direct byte-range "
    "candidate whose validity is deferred to the Stage 3 render check. E3 recovers "
    "documents on which the baseline, lacking any anchor, returns nothing; it is "
    "deliberately a fallback, and its output is flagged as a lower-confidence class "
    "because it applies no sector relocation."
)
h2("3.4.1 C1: cross-reference-stream recovery")
para(
    "Problem. This is the change that matters most for modern relevance. Since PDF 1.5 "
    "the cross-reference table may be a stream: a /Type /XRef object whose body is "
    "FlateDecode-compressed and usually PNG-predicted. Cohen's lexer recognises only "
    "the literal keyword xref, so on a document produced by any current tool it finds "
    "no anchors and recovers nothing."
)
para(
    "Change (C1). For each /XRef marker the index records, the carver walks back to the "
    "enclosing 'N G obj' header (not the nearest indexed object, which may be an "
    "unrelated linearisation dictionary) and parses exactly that one object. When the "
    "object completes, its stream is inflated; where a PNG predictor is declared "
    "(/Predictor 10 or greater) the per-row filters (None, Sub, Up, Average, and Paeth) "
    "are reversed; and each fixed-width entry, whose three field widths are given by "
    "/W, is read under the ranges declared in /Index. Type-1 entries yield object byte "
    "offsets and become anchors identical in kind to those from a classic table; type-2 "
    "entries, which index objects packed inside an object stream, route the enclosing "
    "document to a direct byte-range carve (Stage 2.5) rather than a mapped "
    "reconstruction. A decoded stream is accepted only when it yields at least four "
    "usable entries, which suppresses false positives from /XRef substrings in ordinary "
    "content, and every field interpretation is guarded so that a malformed or hybrid "
    "stream yields no anchors and falls through to E3 rather than aborting the carve."
)
para(
    "Why it helps. C1 restores the identified points for the class of documents the "
    "canonical carver cannot process at all; in Section 5 the baseline recovers none of "
    "the cross-reference-stream instances while the extended carver recovers 79.5% of "
    "them. The decoded offsets are PDF-relative, exactly like a classic table, so the "
    "unchanged Stage 3 machinery consumes them without modification."
)
h2("3.5 Stage 3: reconstruction, repair, validation, and deduplication")
para(
    "Stage 3 reconstructs one PDF per map. A map is loaded into a reassembler that "
    "exposes the image as a virtual file: a read at file position p interpolates the "
    "bracketing anchors to an image offset and returns the disk byte there, with "
    "unit-slope extrapolation between and beyond points. Where forward and reverse "
    "interpolation disagree at a sector boundary the sector is ambiguous; the "
    "reconstructor inserts a candidate point, parses a few kilobytes through Cohen's "
    "discriminator, and keeps the point only if the error count stays at zero (the "
    "original ambiguity-resolution procedure, unchanged), and the consumed bytes are "
    "flushed to the output file. Two engineering changes operate here. A direct-length "
    "fast path (E2) reads a stream body in a single operation when its /Length is a "
    "literal integer, rather than scanning it in small chunks for the endstream "
    "keyword. An over-read bound (E6) clamps the reconstruction at the first %%EOF "
    "beyond the last mapped anchor (recorded as a # BOUND directive when the map is "
    "written), which prevents a sparse-xref document from being extrapolated across "
    "the rest of the image."
)
h2("3.5.1 C2: anchored bi-fragment repair")
para(
    "Problem (FM2). When an object's FlateDecode stream is bifragmented, the break lies "
    "between two consecutive anchors and is marked by nothing: a contiguous read "
    "splices unrelated sectors into the stream, decompression fails, and the page does "
    "not render. Cohen's discriminator detects the error only a few sectors later and "
    "cannot localise it."
)
para(
    "Change (C2). We exploit the fact that the break is bounded by two consecutive "
    "anchors, object N at (p1, d1) and object N+1 at (p2, d2). Under the first-order, "
    "sector-aligned fragmentation model the problem reduces to choosing a single "
    "sector-aligned split a within the inter-anchor interval of length g = p2 - p1: "
    "fragment A runs forward from the image offset d1, fragment B backward from d2, and "
    "the concatenation is accepted when an incremental zlib decompressor reports the "
    "reassembled stream complete (Algorithm 1)."
)
para(
    "We are explicit about prior art here. The decompression-completeness oracle is "
    "Garfinkel's (2007) and Chen et al.'s (2008), and Chen et al. already bound such a "
    "search by cross-reference offsets and iterate the split sector by sector. What C2 "
    "adds is the placement of that search inside Cohen's mapping-function "
    "reconstruction (a single bounded search between two identified points, run on the "
    "already-reassembled bytes) and, through C1, its application to the modern "
    "cross-reference-stream documents that Chen et al.'s classic-table method cannot "
    "reach. The difference is one of integration and applicability rather than "
    "asymptotic cost: both searches are O(g/s) in the inter-offset gap. Concretely, "
    "Chen et al.'s cascade operates as a standalone validator over candidate files and "
    "presupposes a readable classic table; C2 runs inside the reassembler, on bytes "
    "already relocated by the mapping function, needs no re-parse of the surrounding "
    "document, and inherits C1's anchors, so it fires on documents Chen et al. cannot "
    "open at all. The measured consequence of this difference is visible in Section 5: "
    "on the bi-fragmented corpus, where both methods can read every table, our carver "
    "reaches 71 of 80 against Chen's 36, and on the cross-reference-stream corpus Chen "
    "et al. recover a third of the instances where C2-through-C1 recovers four fifths."
)
para(
    "Why it helps. The cost is at most g/s decompression trials per broken stream, "
    "independent of the image size, with no disk-wide search and no re-parse of the "
    "document. The controlled ablation in Section 5 isolates the effect: exact recovery "
    "on the bi-fragmented disks rises from 64 of 80 documents to 71 of 80, while "
    "contiguous data is untouched, because the stage only fires after a decompression "
    "failure."
)
para("Algorithm 1: Anchored bi-fragment repair", italic=True)
alg = ("Input:  image I, carved bytes C, anchor pair (p1, d1) and (p2, d2), sector size s\n"
       "Output: repaired byte range, or none\n"
       "1.  g = p2 - p1                      (inter-anchor gap, a multiple of s)\n"
       "2.  z = offset of the zlib data after the stream keyword within C[p1:p2]\n"
       "3.  if C[p1+z : p2+margin] already decompresses to completion: return none\n"
       "4.  for each sector-aligned split a in (z, g]:\n"
       "5.        A = I[d1 : d1+a];   B = I[d2-(g-a) : d2]\n"
       "6.        if len(A)+len(B) = g and (A concatenated with B), from offset z,\n"
       "7.                                  decompresses to completion: return A++B\n"
       "8.  return none")
p = doc.add_paragraph()
r = p.add_run(alg)
r.font.name = "Consolas"
r.font.size = Pt(9)
figure(r"<repo>\figures\fig3_c2repair.png", 6.2,
       "Figure 3. Anchored bi-fragment repair (C2). A FlateDecode stream is split across "
       "a disk gap of length g. A naive contiguous read runs straight through the gap, "
       "so decompression fails and the page does not render. The repair discards the "
       "gap and joins the two fragments, searching only the sector-aligned splits "
       "between the two anchors and accepting the join when the stream decompresses to "
       "completion (zlib EOF).")
para(
    "Each accepted reconstruction is then routed through an independent production "
    "renderer (E4): the qpdf-based pikepdf parser, which shares no code with our "
    "carver, accepts a candidate only if it opens and exposes a non-empty page tree, "
    "and otherwise retains it on disk as a suspect file for analyst review. This "
    "replaces the canonical model's reliance on its own lexer-error count, which is "
    "least reliable on the damaged-anchor inputs that motivate this work. Finally the "
    "accepted outputs are deduplicated (E5): incremental-update tables whose "
    "cross-references are supersets of one another are collapsed before "
    "reconstruction, and any residual byte-identical output is removed by SHA-256 "
    "comparison; the final count is therefore of distinct documents, not of repeated "
    "reconstructions of one document."
)
h2("3.6 Forensic soundness and evidence handling")
para(
    "A carver is an evidence-handling tool before it is a recovery tool, so we state "
    "the properties that make its output defensible. First, the carver opens the "
    "source image strictly read-only in every code path; we verified this by auditing "
    "every file-open in the released code, and no path opens the evidence for "
    "writing. Second, each run computes the SHA-256 of the evidence image before "
    "analysis begins and again after it completes, and appends both digests with "
    "timestamps to a per-run log; a mismatch would be reported loudly, and the "
    "matching pair gives the examiner a checkable record, for that specific run, that "
    "analysis did not alter the evidence. Third, the map file is itself an exhibit: "
    "because every reconstruction is materialised from an explicit mapping, each "
    "recovered byte range is traceable through its map line to the exact image offset "
    "(and therefore disk sector) that supplied it. An examiner, or an opposing "
    "expert, can verify any part of a recovered document against the source image "
    "with nothing more than the map file and a hex viewer. Signature carvers cannot "
    "produce this trail, because they never form an explicit mapping; the bytes they "
    "emit have no recorded provenance beyond a start offset. Fourth, files that fail "
    "validation are retained and labelled as suspect rather than deleted, so the "
    "tool's own filtering decisions remain reviewable. We are careful about the "
    "claim's boundary: these mechanisms support chain of custody but do not by "
    "themselves constitute it, since chain of custody also covers acquisition, "
    "storage, transport, and access control before the image ever reaches an "
    "analysis tool."
)

h2("4.3 Scoring")
para(
    "Ground truth for the synthetic and NIST corpora is the set of planted source "
    "documents. A carved file is matched to ground truth by a three-tier content "
    "cascade: an exact SHA-256 file hash; failing that, a per-page render hash (the "
    "MD5 of each page's rasterised pixel buffer at 72 dpi, compared as an ordered "
    "tuple), which is the primary tier because every reconstructing carver "
    "re-serialises its output, so the file hash rarely survives even a perfect "
    "recovery while the rendered pixels do; and failing that, a hash of the "
    "concatenated extracted text. The render hash is produced by the MuPDF engine, "
    "which is a different renderer from the qpdf-based validator SCAR uses internally "
    "as its acceptance filter (E4). A file is therefore counted as recovered only when "
    "its rendered content matches the planted original under an engine independent of "
    "the one that admitted it, so the acceptance filter and the evaluation oracle are "
    "not the same check, and the criterion is content equivalence to the known "
    "original rather than mere renderability. Each carved file then receives "
    "exactly one label (Table 2). We report recall (Faithful / planted) and a "
    "false-accept rate "
    "(False accepts / (Faithful + Partial + False accepts)). Redundant reconstructions "
    "of a document already recovered are counted as duplicates, not false accepts: a "
    "redundant correct file and a fabricated one are different failure modes, and "
    "conflating them would penalise tools that simply lack a deduplication pass. In "
    "the depth corpus only the deliberately fragmented targets count toward recall; a "
    "recovered contiguous distractor is real data, so it is excluded from scoring "
    "rather than miscounted as a false accept. The DFRWS 2007 image is the one "
    "exception to content-tier scoring: its source documents were never released, "
    "only their MD5 digests, so that corpus is scored by exact whole-file MD5 alone. "
    "The scoring scripts are released with the corpus generators, and the same "
    "scripts scored all six tools."
)

        ["Partial", "Rendered pages are an ordered subset of a planted document's pages, or the text hash matches but the render does not."],
        ["Duplicate", "Matches the same planted document as an already-counted equal-or-better candidate (redundant, not wrong)."],
        ["False accept", "Renders as a valid PDF but matches no planted document."],
        ["Junk", "Does not render as a valid PDF."],
    ])

    sig = "yes" if ("e-" in p) else "no"
    rows2.append([label, "%d (%.1f%%)" % (ks, ks / n * 100),
                  "%d (%.1f%%)" % (kc, kc / n * 100), "%d / %d" % (b, c), p, sig])
table(["Experiment (N docs)", "Ours: recovered", "Chen: recovered",
       "b / c", "McNemar p", "p<0.05"], rows2)
caption("Table 12. Paired McNemar test of faithful recovery, our carver versus the "
        "Chen et al. (2008) baseline, the nearest prior method to contribution C2. As "
        "with Cohen, the discordance is entirely one-directional (c = 0 on every "
        "corpus): Chen recovers no document our carver misses. Significance holds on "
        "all four synthetic and contribution corpora; the two real-image corpora are "
        "too small to reach it.")

h2("5.8 Limitations and threats to validity")
para(
    "Several limitations bear on how far these results generalise, and we collect "
    "them here rather than leave them scattered through the discussion. The most "
    "basic concerns the corpus itself. The fragmentation in the 127 synthetic images "
    "is injected by our generators rather than produced by a live filesystem. That is "
    "what lets us hold ground truth exactly, but it also means the fragment "
    "placements, however varied and carefully seeded, are not drawn from a real "
    "allocation process. The two external corpora offset this only partly, and a "
    "study on evidence-scale images with natural fragmentation remains the strongest "
    "validation this work could receive."
)
para(
    "Two of the five baselines, Cohen and Chen et al., are our own reimplementations. "
    "We checked them behaviourally, as Section 4.2 describes, but not bit-for-bit "
    "against the original code, so the comparative margins, including the runtime "
    "factor, should be read as comparisons between implementations under one "
    "configuration rather than between the methods in the abstract."
)
para(
    "The contributions themselves have boundaries worth stating plainly. The anchored "
    "repair handles the first-order, two-fragment case with a sector-aligned split, "
    "and it assumes the second fragment runs contiguously back from the next anchor. "
    "Higher-order and interleaved fragmentation sit outside its scope, and every tool "
    "we measured, ours included, fails almost entirely on the braided scenario. The "
    "depth sweep likewise shows that reassembly has a practical ceiling near four "
    "fragments. On the decoding side, the cross-reference-stream decoder resolves "
    "type-1 entries directly but sends documents whose objects live inside compressed "
    "object streams to a whole-document byte-range carve instead of unpacking the "
    "object stream, so the most heavily compressed modern documents are recovered "
    "only when they happen to be contiguous."
)
para(
    "A further caution concerns the repair oracle. The repair accepts the first "
    "sector-aligned split that decompresses to completion, and a decompression test "
    "can in principle accept a wrong split that happens to inflate cleanly. Our "
    "content-level scoring would record such a case as a non-faithful output rather "
    "than a recovery, so it cannot silently inflate our results, but we have not "
    "separately measured how often the oracle is fooled, and adding a content check "
    "to the acceptance step would be a worthwhile hardening. Finally, although the "
    "stream-encoded documents in the corpus come from more than one producer family, "
    "office and LaTeX toolchains along with organically produced files from the "
    "GovDocs collection, a systematic sweep across every major producer's predictor "
    "and object-stream choices would strengthen the generality claim further.")

# ====================== 6. Conclusion and Future Work =====================
h1("6. Conclusion and Future Work")
para(
    "The semantic model that has defined PDF carving since Cohen (2007) rests on two "
    "assumptions that no longer hold for contemporary evidence: that the "
    "cross-reference information is a classic xref table, and that a fragmentation "
    "discontinuity coincides with a structural marker the discriminator can localise. "
    "Each produces a concrete failure: no recovery for the PDF-1.5+ "
    "cross-reference-stream documents that every mainstream producer now emits (FM1), "
    "and corruption of a bi-fragmented compressed stream whose split lies between two "
    "identified points (FM2). We have presented an extension of Cohen's carver that "
    "addresses both within his mapping-function framework, keeping its mathematical "
    "core unchanged."
)
para(
    "Two contributions carry the work. C1 decodes the cross-reference stream to "
    "restore identified points for documents the canonical carver cannot read at all: "
    "on the 39 such instances in our corpus the baseline recovers none and the "
    "extended carver recovers 31. C2 repairs a bi-fragmented compressed stream by "
    "bounding the reassembly search to the single interval between two consecutive "
    "identified points and validating each candidate by decompression completeness; "
    "the oracle and the offset-bounding are due to Garfinkel (2007) and Chen et al. "
    "(2008), and C2's own contribution is to re-anchor that search inside the "
    "mapping-function model and, through C1, to bring it to modern documents. On the "
    "bi-fragmented corpus the carver recovers 71 of 80 documents against 36 for both "
    "reimplemented baselines, and the ablation ties the repair stage's contribution "
    "to the bi-fragmented images alone. On the external NIST reference the carver "
    "matches the original exactly, showing no regression on classic documents, and "
    "on the DFRWS 2007 image, scored by its strict MD5 answer key, the original "
    "remains one document ahead, a result we report and explain rather than "
    "obscure. The extended carver processes that image 15.3 times faster than the "
    "baseline."
)
para(
    "Three limitations bound the present work. Documents whose objects live inside "
    "compressed object streams (type-2 cross-reference entries) are handled by a "
    "direct byte-range carve of the enclosing document rather than by unpacking the "
    "object stream itself; full object-stream resolution would extend mapped "
    "reconstruction to the most heavily compressed modern documents. The anchored "
    "repair handles the first-order, two-fragment case; higher-order and interleaved "
    "(braided) fragmentation, on which every tool we measured fails almost "
    "completely, remains open. And while the planted documents are real and the NIST "
    "and DFRWS images are external, the fragmentation in our synthetic corpora is "
    "injected for exact ground truth; a study on evidence-scale images with natural "
    "fragmentation is the natural next step. We release the implementation, the "
    "seeded corpus generators, the manifests, and the scoring scripts so that every "
    "number in this paper can be regenerated from the released artefacts."
)
